# Лаба №7  


## Структура модулей

* **`src/lab07/search.py`** — алгоритмы поиска и решения задачи Two Sum:
  * `linear_search(nums, x)` — линейный поиск индекса первого вхождения элемента (`O(n)`).
  * `binary_search(sorted_nums, x)` — бинарный поиск по отсортированному списку (`O(log n)`).
  * `two_sum_brute(nums, target)` — поиск пары индексов с заданной суммой полным перебором (`O(n^2)`).
  * `two_sum_fast(nums, target)` — поиск пары индексов за один проход с использованием словаря (`O(n)`).
* **`src/lab07/sorting.py`** — квадратичные сортировки, возвращающие новый список без изменения исходного:
  * `bubble_sort(nums)` — сортировка пузырьком с флагом досрочного выхода при отсутствии обменов.
  * `insertion_sort(nums)` — сортировка вставками.
  * `selection_sort(nums)` — сортировка выбором.
* **`src/lab07/check.py`** — автоматическая проверка всех функций против эталонных `sorted()`, `list.index()` и `in` на случайных и граничных данных.
* **`src/lab07/bench.py`** — замеры времени выполнения через `timeit` на фиксированных случайных данных (`random.seed(42)`) и экспорт результатов в `data/lab07/bench.csv`.

## Выводы

При увеличении списка в 10 раз (с 1 000 до 10 000 элементов) пузырьковая сортировка замедлилась в ~112 раз (`0.049 с` → `5.533 с`), потому что её сложность $O(n^2)$, а встроенный `sorted()` — в ~18 раз (`0.0001 с` → `0.0019 с`), потому что у него сложность $O(n \log n)$ и реализация на C.

Бинарный поиск бесполезен на неотсортированном списке, так как без порядка элементов он выдаёт неверный индекс; для 1–2 запросов быстрее линейный поиск за $O(n)$, а на 10 000 запросов однократная сортировка окупается и ускоряет поиск в 655 раз (`0.025 с` против `16.395 с`).

Проверка `check.py` выполнила 500 прогонов (300 для сортировок, 100 для поиска, 100 для Two Sum), расхождений с эталоном не нашла и завершилась со статусом `OK`.
